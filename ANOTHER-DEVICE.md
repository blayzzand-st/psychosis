# Запуск на другом устройстве и доверие к сертификату

Ниже два разных случая: приложение запускается целиком на новом компьютере
или другой компьютер только открывает уже работающий сервер по сети.
Основные команды приведены для PowerShell на Windows.

## Вариант 1. Перенос всего приложения на новый компьютер

Понадобятся Git, Docker Desktop с Linux containers, Python 3 и OpenSSL.
В Git for Windows OpenSSL обычно уже есть — скрипт умеет находить его там.
Node.js и локальный PostgreSQL для запуска всего приложения в Docker не нужны.

### 1. Скачать проект

```powershell
git clone https://github.com/blayzzand-st/psychosis.git
cd psychosis
```

Для существующей копии: `git pull --ff-only` из её папки.

### 2. Создать сертификаты именно на этом компьютере

```powershell
python scripts/init_tls.py --isu 368833
```

Скрипт создаёт в `.local/tls` собственный CA и подписанные им сертификаты
frontend/API. Они подходят для localhost и 127.0.0.1.
Ключи и сертификаты намеренно не лежат в GitHub. Выпуск нового TLS-сертификата
не меняет пароли, TOTP или ключи JWT в переносимой базе.

Если сообщение говорит, что OpenSSL не найден, установить Git for Windows
с OpenSSL либо добавить установленный OpenSSL в PATH, затем повторить команду.

### 3. Установить доверие к новому CA

На этом же компьютере, из корня проекта:

```powershell
Import-Certificate -FilePath .local/tls/ca.crt -CertStoreLocation Cert:\CurrentUser\Root
```

Импортируется **ca.crt**, не server.crt и не какой-либо `.key`.
Сертификат попадает в доверенные корневые центры текущего пользователя.
Chrome/Edge после этого должны доверять серверному сертификату. Если браузер
уже был открыт, полностью закрыть и открыть его снова.
Описание команды: [Microsoft Import-Certificate](https://learn.microsoft.com/en-us/powershell/module/pki/import-certificate).

Альтернатива через интерфейс Windows: открыть ca.crt → «Установить сертификат» →
«Текущий пользователь» → «Поместить все сертификаты в следующее хранилище» →
«Доверенные корневые центры сертификации».

Для Firefox при необходимости: Настройки → Приватность и защита → Сертификаты →
Просмотр сертификатов → Центры сертификации → Импортировать ca.crt и разрешить
доверие для идентификации сайтов. Описание импорта корня:
[Mozilla](https://wiki.mozilla.org/CA/Changing_Trust_Settings).

### 4. Перенести данные отдельно от GitHub

Скопировать свежие файлы `.dump` и `.dump.sha256` в `backend/backups` нового
проекта и выполнить [RESTORE.md](RESTORE.md). Дамп содержит также TOTP-секреты,
парольные хэши и ключи JWT; его нужно передавать отдельно и хранить как чувствительный файл.

Если восстановить дамп с настроенным администратором, сохранятся его пароль и
TOTP-секрет. Если администратор был удалён до создания копии, откроется первоначальная
настройка. Отсутствие восстановления создаёт пустую БД, а не копию старых данных.

### 5. Запустить

```powershell
docker compose up -d --build --wait
```

Открыть **https://localhost:8080**. Нужен именно HTTPS.
Проверка: **https://localhost:8080/api/health**, ожидается `{"status":"ok"}`.

Если нужны локальные frontend/backend с контейнерной БД, сначала установить
зависимости по README и настроить backend/.env, затем:

```powershell
.\start-local.ps1 -TrustCa
```

Тогда адрес — **https://localhost:5173**. Флаг -TrustCa выполняет тот же импорт
ca.crt; повторные запуски возможны просто через `.\start-local.ps1`.

## Вариант 2. Другой компьютер открывает сервер по локальной сети

Здесь на клиентском компьютере приложение и БД не запускаются. На нём нужно
доверие к **CA сервера**, а не новый собственный CA.

### На компьютере-сервере

Узнать его фактический адрес в локальной сети. В примере ниже `192.168.1.10`
нужно заменить своим адресом:

```powershell
python scripts/init_tls.py --isu 368833 --host 192.168.1.10
```

При существующих ca.crt/ca.key скрипт сохраняет CA и перевыпускает сертификаты
с дополнительным IP в SAN. Если вход будет по DNS-имени, добавить также
`--host имя-сервера`, которое клиент действительно сможет разрешить.

В корневом `.env` добавить или изменить строку, сохранив остальные настройки:

```dotenv
APP_HOST=0.0.0.0
```

Для полного Docker-варианта:

```powershell
docker compose up -d --build --force-recreate --wait
```

Порт 8080 должен быть доступен с клиентского компьютера в доверенной локальной
сети. При блокировке проверить правила брандмауэра. Порт БД для браузера не нужен.
Локальный Vite на 5173 по умолчанию слушает только loopback; этот вариант инструкции
использует Nginx из полного Docker-запуска.

### На клиентском компьютере

Скопировать **только `.local/tls/ca.crt` с сервера**, например в `Downloads`.
Установить доверие:

```powershell
Import-Certificate -FilePath "$env:USERPROFILE\Downloads\ca.crt" -CertStoreLocation Cert:\CurrentUser\Root
```

Затем открыть **https://192.168.1.10:8080** с фактическим IP сервера.
`localhost` на клиентском компьютере указывает на сам клиент, не на сервер.
Закрытые ca.key/server.key/backend.key на клиент не копируются.

## Если предупреждение о сертификате осталось

| Сообщение/причина | Что проверить |
| --- | --- |
| Неизвестный издатель / authority invalid | Импортирован ли правильный ca.crt от того CA, который подписал текущий серверный сертификат |
| Несовпадение имени / name invalid | Открываемый IP или DNS должен быть в SAN; выпуск localhost-сертификата не покрывает произвольный IP |
| Сертификат просрочен / date invalid | Дату и время компьютера и срок сертификата; при необходимости перевыпустить серверные сертификаты и перезапустить сервер |
| Старый CA после перевыпуска | Если создавался другой корень, установить доверие к нему; одинаковое имя CA не означает одинаковый ключ |
| Не открывается вообще, timeout/refused | Docker, порт, APP_HOST, адрес и сеть; это ещё не ошибка проверки сертификата |
| Работает страница, но не API | API-контейнер healthy, сертификат backend и его SAN, журналы proxy/backend |

Отключать проверку сертификатов или обходить предупреждение браузера не требуется.
Подробная техническая схема и проверочные команды: [TLS.md](TLS.md).
